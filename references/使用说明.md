# 使用说明

## 依赖与移动

把整个lishi-tuwen文件夹复制到新位置。Python3.10+安装requirements.txt中的Pillow12.1+和numpy2+；离线环境先用自己的Python包镜像/缓存安装。Skill内置三个开源字体及OFL、所有组件/验证脚本、模板和三套自有示例，没有依赖原项目工具目录。原始历史图片/真实mask需要调用者合法取得并提供，不能把“自带依赖”理解为任意题材素材都已取得。

所有命令从Skill目录示例；工作目录可放任意位置，脚本参数接收该目录。页面脚本素材路径相对脚本所在目录；`--assets-root`显式改变素材根目录，不能同时假定原项目固定位置。相对路径不得越根；绝对运行参数可以传入，但不写进可分发页面脚本。

## 四个入口

|脚本|输入|输出与失败行为|
|---|---|---|
|new_note.py|topic、tone、out；pages默认10|新工作目录、页面脚本、文稿/事实/许可模板；非空目录拒绝覆盖|
|check_all.py|页面脚本、pages或products、可选report/assets-root/out|统一指标、实际错误、样稿/正式范围；错误返回1，不改输入|
|blind_test.py|参考目录、候选目录、kind、out、随机seed、可选faces/reference-list|3:4随机中性编号图；答案另存；素材不足不重复凑数，检测失败不跳过|
|package.py|note、pages、out、可选assets-root/cover-c|先重验，成功整理D主封面/内页/预览/文稿/清单；拒绝覆盖、不会发布|

小样：`new_note.py --topic '新历史题' --tone dark --pages 3 --mode sample --out 工作/小样`。总共三页（D＋两内页）；只验证流程和局部技术规则，不宣称达到完整8–12页/15源配额。默认正式稿不允许自动套小样豁免。

统一检查已整理成品时，`--products`按01-封面.png、02.png等读取；默认读取示例旁渲染基准.json。普通工作用`--pages rendered`读取p01.png等与render-report.json。三套示例原图由素材清单列出，不随包携带。

## Vision、人脸与mask

macOS执行：

```bash
swift scripts/检测人脸.swift 工作/新选题/人脸输入.json 工作/新选题/人脸结果.json
swift scripts/cutout.swift 工作/新选题/assets/人物.jpg 工作/新选题/assets/人物透明.png
swift scripts/ocr.swift 工作/新选题/assets 工作/新选题/OCR.json
```

人脸输入JSON为图片路径数组；结果包含path/status/detector/faces。faces为归一化左上原点[x,y,w,h]。把成功结果写入图像元素face_boxes与face_detection_method；必要时群像分区检测并映回原图，误检由人工记录剔除理由，不悄悄丢弃。

cutout需macOS14+和可用Vision前景分割；生成完整RGBA画布，透明alpha是真正的人物形状。subject_mask用于人物实高测量，要与原照片同尺寸，显式crop时同步裁片。纸面档案/场景不要给假的实心整图mask充当人物。

OCR兼容jpg/jpeg/png，结果为真实转录与归一化框；失败状态保留。非macOS需已有/人工转录、人工抠图和手动确认脸框（method=manual-verified）。没有确认不要传空列表冒充无人脸。Python渲染及指标无需Swift；拼图遇非3:4参考且未提供框时，本机Vision不可用则明确失败。

## 相对素材与复现

```bash
python3 scripts/render.py examples/03-泳衣量腿/页面脚本.json --assets-root 外部历史素材根目录 --out 工作/复现泳衣
python3 scripts/check_all.py examples/03-泳衣量腿/页面脚本.json --pages 工作/复现泳衣 --assets-root 外部历史素材根目录 --out 工作/复现检查.json
```

示例素材清单的path相对给定根目录，带SHA256。外部根目录可直接是拥有这些材料的旧工程根，或按清单构建同样相对目录；只读取图片及缓存mask，不调用旧工程代码。拿不到某素材时明确报缺图；不能生成替代图却声称像素复现。

## 盲测

内页默认9参考＋4新稿，封面只放D。参考集可按纸张/亮图预先分层抽样，再通过reference-list传入相对参考目录的文件数组。faces清单key为reference/相对文件或candidate/相对文件，value为人工确认框数组或status=success、faces对象。

默认参考目录递归读取其preview子目录或目录直属图片；inner排除01/p01/封面与备选，cover只取主封面。多篇示例在自己的preview子目录可作流程夹具，但不能冒充作者盲测。输出随机seed与真实来源单独进入盲测答案；共享盲测时只给拼图。

## 正规授权标题接入

授权登记与凭证留工作目录research/授权凭证，必填授权方、字体版本/SHA、范围、期限、对应账号主体。用户合法提供字库后：

```bash
python3 scripts/换标题字体重出.py --script 工作/新选题/页面脚本.json --font 工作/新选题/fonts/licensed/正版标题.ttf --out 工作/新选题/授权版 --assets-root 工作/新选题 --index 0
```

脚本先验证字库、逐字缺字与页面，保留正文；默认改含headline/cover-title/heading的页面。`--pages 1,4,7`可限定页码；`--weight 700`只适用于变量字库，静态字库省略。没有有效文件则停止，不生成冒充正版的图。合法使用范围仍需人工核对，技术加载成功不等于授权完成。

render可配置fonts.licensed_headline的path/index/weight，覆盖三个标题key。缺失/索引/轴错误警告并回退宋体700，check_all视为失败；正常默认仍是马善政清晰B。商业字库和凭证绝不加入可分发Skill。

## 检查与差异

check_all包括尺寸、脚本/成图哈希、比例/裁片/脸框、色调、无灰卡、文字/抠图和署名碰撞、字形/标点/影、圆盘、暗篇交替/留白/丰富度、浅篇密度/正文/照片/圈及同源复用。当前正式例子若有旧漏检，错误照样报告，不自动沿用“验收通过”抹去错误。

可运行验证排版、验证标题效果、验证圆盘肖像、验证整篇色调、验证混合背景、验证交替节奏和验证浅色调的自包含正反例。它们不需要原作或项目照片。完整素材条件下继续用check_all验证实际页，而非只跑合成夹具。

跨平台像素一致性取决于Pillow/FreeType版本。相同字体文件、轴值、脚本与素材应可复现；不同环境必须逐页比对，不能承诺未经运行的平台逐字节相同。
